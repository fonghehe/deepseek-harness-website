# معماری

`landing-page.tsx` صفحه را می‌سازد. `layout/`، `controls/` و `sections/` ساختار، کنترل و محتوا را جدا می‌کنند. `previews/` تصویرسازی و CSS، `motion/` کد Framer Motion و `graphics/` صحنه‌های Three.js، هندسه و شیدر را نگه می‌دارند.

صفحه زبان را اعتبارسنجی و واژه‌نامه را به اجزا منتقل می‌کند. سرور و کلاینت همان JSX را دارند؛ چیدمان `lang` و `dir` را تعیین می‌کند. RichText فقط تگ‌های توافق‌شده را می‌پذیرد. HTML ضبط‌شده یا برنامهٔ کامپایل‌شدهٔ سایت اصلی بارگذاری نمی‌شود.

`use-demo-scene.ts` توقف کاربر، دیده‌شدن، زبانهٔ فعال و کاهش حرکت را ترکیب می‌کند. CSS پیشرفت را در توقف حفظ می‌کند؛ سناریو پس از چرخه عوض می‌شود. چهار روایت ۲۲، ۱۷٫۵، ۱۱ و ۱۵ ثانیه طول می‌کشند.

Three.js هنگام نیاز بارگذاری می‌شود؛ حداکثر 30fps و وضوح پیکسل CSS دارد و بیرون صفحه یا در پس‌زمینه متوقف می‌شود. کاهش حرکت از راه‌اندازی GPU جلوگیری می‌کند. هندسه، مواد، بافت و رندرکننده آزاد می‌شوند. Framer Motion فنر سربرگ، ورود بخش‌ها و پرسپکتیو پیمایش را مدیریت می‌کند.

`pnpm build` ابتدا VitePress را در `public/docs` و سپس Next.js را می‌سازد. ناوبری مستندات جهت و SEO را به‌روز می‌کند. کش سرور origin و زبان/مسیر مقاله را جدا می‌کند؛ حداکثر ۱۲۸ ورودی را پنج دقیقه نگه می‌دارد و رندر ناموفق را حذف می‌کند. ETag منطبق پاسخ `304` بدون بدنه می‌دهد.

Pages از `build:pages` و `check:pages` با `SITE_URL` کامل استفاده می‌کند. فرادادهٔ ثابت هنگام ساخت تعیین می‌شود؛ کش و ETag برنامه مربوط به حالت سرورند. خروجی گرفتن منبع کاری را تغییر نمی‌دهد. راهنما در `DEVELOPMENT.md` است.

```text
src/components/
├── landing-page.tsx
├── layout/
├── controls/
├── sections/
├── previews/
├── motion/
├── graphics/
├── shared/
└── styles/

page.tsx → locale + dictionary → LandingPage → Next.js SSR
/docs/ → /docs/en/ → VitePress article
```
