# 官网建设要点

修改页面或准备发布时，可以按下面的清单检查。根据改动选择验证项，并记录实际结果。

## 页面检查清单

| 方面       | 验收结果                                   | 项目证据                |
| ---------- | ------------------------------------------ | ----------------------- |
| 信息组织   | 不播放全部动画也能理解定位和下一步         | 首屏、分区和详情折叠    |
| 品牌一致性 | 字体、图标、表面一致，favicon 为黑色       | 本地品牌和 CSS          |
| 响应式     | 长标签、菜单和技术块适配窄屏               | 阿拉伯语 390px 检查     |
| 导航       | 水合后链接有效，语言切换保留参数和片段     | 语言和路由测试          |
| 渐进增强   | 无 JavaScript 时核心文字、链接和详情可用   | 无脚本浏览器场景        |
| 无障碍     | 焦点合理，减少动态效果不隐藏内容           | 键盘、动效和 axe 检查   |
| 国际化     | 多语言内容、元信息和文章对齐               | `check:i18n` 与文档测试 |
| 可发现性   | canonical、alternate、分享信息属于当前页面 | 响应与客户端导航检查    |
| 交付       | 不串域名或语言，304 无响应体               | 缓存测试                |
| 资源       | 输入依赖齐全，适配可重复                   | manifest 和资源校验     |

人工验收还需关注阅读顺序、翻译、换行、阿拉伯语混排和行动文案。截图与单一分数不能证明全部结果。

## 应提交的源码与应忽略的产物

| 路径                                                                | 是否提交 | 原因                             |
| ------------------------------------------------------------------- | -------- | -------------------------------- |
| `src/`、各语言 Markdown、`docs/.vitepress/`                         | 是       | 可维护源码和配置                 |
| `src/components/`、`src/hooks/`                                     | 是       | 自有组件与动效生命周期源码       |
| `tests/fixtures/assets.json`                                        | 是       | 静态输入清单与 hash              |
| `public/brand/`、`public/fonts/`、`public/icons/`、`public/images/` | 是       | 品牌、字体、文件图标与中文二维码 |
| `.next/`                                                            | 否       | 当前项目可重新构建的输出         |
| `public/docs/`                                                      | 否       | VitePress 可重新生成的文档输出   |
| VitePress 缓存、报告、`node_modules/`                               | 否       | 缓存、测量产物、已安装依赖       |
| `.env.example`、共享编辑器/agent 文件                               | 是       | 可移植配置与说明                 |
| `.env.local`、个人覆盖、凭证                                        | 否       | 私密或机器专属状态               |

`public/harness-source` 和捕获 HTML 已删除。网站 JS/CSS 由本仓库维护的组件和样式经过 `pnpm build` 生成。只保留品牌、字体、文件图标与中文二维码等静态输入，构建中的 hash 文件属于可重新生成的输出。

## 开发环境

使用仓库声明的 Node、pnpm 和锁文件。共享编辑器设置只描述项目任务，个人 MCP、凭证和历史状态留在本地。`AGENTS.md` 是统一指令入口，`AGENT.md` 是兼容说明，不代表所有工具自动识别单数文件。Git 和索引忽略规则不能替代文件权限。

## 修改内容后的验证

1. 修改可维护内容或文档，同步其他语言和共享描述。
2. 官网检查初始 HTML 与水合后 DOM；文档检查文章间和语言间导航后的状态。
3. 运行格式、翻译和构建检查；触及路由、SEO、方向或控件时增加相关浏览器回归。
4. 检查窄屏、减少动态效果和阿拉伯语 命令标点。

```sh
pnpm format:check
pnpm check:i18n
pnpm docs:build
pnpm verify
E2E_PORT=3101 pnpm test:e2e
```

使用空闲端口，浏览器测试前完成生产构建。文档改动不应顺带修改演示组件；hash 不符时先查差异，再决定是否有意更新校验值。

## 发布与部署清单

- `pnpm build` 先生成文档，部署保留完整 `public`。
- 配置实际生产 `SITE_URL`，在部署域名检查 canonical 与分享 URL。
- 验证文档默认英文、多语言入口、404、sitemap 和黑色图标。
- 检查演示、复制、下载与动态 chunk 请求。
- 确认 HTML、框架生成 chunk 和真正内容 hash 资源使用不同缓存策略。
- 分开报告本地结果、远端 CI 和线上验收，不把构建通过等同于部署成功。

## 性能与长期维护

载荷和 HTML 大小要结合 LCP、CLS、阻塞时间观察。热缓存计时衡量服务端交付，不代表浏览器执行成本消失。历史基线不得为了通过检查而覆盖；扩写文章时应明确评审内容体积预算，不放宽无关官网页面限制。

通过组件、演示时钟与 CSS 修改场景，保持暂停、离屏和减少动态效果的契约。静态输入变更后经评审更新 hash。中文页脚保留微信二维码，其他语言页脚统一跳转 `https://x.com/deepseek_ai`。

继续[学习路径](../learning/)完成实践。

## 自动检查之外的验收

用键盘检查语言与下载菜单、Escape 和焦点恢复，用读屏器验证复制反馈。在真实手机检查滚动与动画阶段。阿拉伯语还需检查长文案和混合方向的命令。记录浏览器、设备、动态效果设置和证据。译文需由母语使用者确认，字段校验不能替代语言审校。

```sh
pnpm verify:full
SITE_URL=https://example.github.io/repository/ pnpm build:pages
SITE_URL=https://example.github.io/repository/ pnpm check:pages
SITE_URL=https://example.github.io/repository/ pnpm perf:pages
```
