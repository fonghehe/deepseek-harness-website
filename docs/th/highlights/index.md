# แนวทางพัฒนาฝั่งหน้าเว็บ

## ข้อมูลและการควบคุม

เรียงจากประโยชน์ไปสู่ตัวอย่าง รายละเอียด และการลงมือ ใช้ลิงก์จริงและตัวควบคุม HTML ตรวจคีย์บอร์ด Escape การคืนโฟกัส เมนูบนจอแคบ และการใช้งานเมื่อปิด JavaScript

## ภาษาและ SEO

พจนานุกรม ป้ายสำหรับเทคโนโลยีช่วยเหลือ เมทาดาทา เมนู และบทความต้องสอดคล้องกัน RTL ใช้ CSS แบบ logical แต่โค้ดยังคง LTR ตรวจ canonical, hreflang, ข้อมูลที่มีโครงสร้าง และข้อมูลแชร์ให้ตรงกับหน้าปัจจุบันหลังเปลี่ยนหน้าด้วยไคลเอนต์ด้วย

## ทรัพยากรและหลักฐาน

คอมโพเนนต์ shader, CSS, Markdown และไฟล์ต้นทางเป็นสิ่งที่ดูแลโดยตรง `tests/fixtures/assets.json` ตรวจความถูกต้อง ส่วน `.next`, `public/docs` และรายงานเป็นผลลัพธ์ที่สร้างขึ้น เรื่องแบรนด์และสิทธิ์อยู่ใน `NOTICE.md`

วัดปริมาณข้อมูล LCP, CLS และเวลาบล็อกซ้ำ รวมถึงบนอุปกรณ์จริง อย่าเปลี่ยน baseline เพื่อกลบปัญหา ผลทดสอบในเครื่อง CI ระยะไกล และการตรวจภาษาโดยมนุษย์ยืนยันคนละเรื่อง
