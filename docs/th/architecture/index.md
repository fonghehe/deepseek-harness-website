# สถาปัตยกรรม

`landing-page.tsx` ประกอบหน้าเว็บ โดย `layout/`, `controls/` และ `sections/` แยกโครงสร้าง ตัวควบคุม และเนื้อหา `previews/` เก็บภาพสาธิตและ CSS ส่วน `motion/` ใช้ Framer Motion และ `graphics/` ดูแลฉาก Three.js รูปทรง และ shader

หน้าตรวจสอบภาษาและส่งพจนานุกรมให้คอมโพเนนต์ เซิร์ฟเวอร์และไคลเอนต์ใช้ JSX ชุดเดียวกัน ส่วน layout กำหนด `lang` และ `dir` RichText รองรับเฉพาะแท็กที่ตกลงไว้ ไม่มีการนำ HTML ที่บันทึกจากเว็บต้นฉบับหรือรันไทม์ที่คอมไพล์แล้วกลับมาใช้

`use-demo-scene.ts` ประสานการพักโดยผู้ใช้ การอยู่ในหน้าจอ แท็บที่ใช้งาน และการลดการเคลื่อนไหว CSS รักษาความคืบหน้าเมื่อพัก และเปลี่ยนสถานการณ์เมื่อจบรอบ เรื่องราวทั้งสี่ใช้เวลา 22, 17.5, 11 และ 15 วินาที

Three.js โหลดเมื่อจำเป็น จำกัดที่ 30fps และความละเอียดพิกเซล CSS พักเมื่ออยู่นอกหน้าจอหรือแท็บเบื้องหลัง และไม่เริ่ม GPU เมื่อขอลดการเคลื่อนไหว มีการคืนทรัพยากรรูปทรง วัสดุ พื้นผิว และตัวเรนเดอร์ Framer Motion จัดการสปริงของส่วนหัว การปรากฏของส่วนต่าง ๆ และมุมมองขณะเลื่อน

`pnpm build` สร้าง VitePress ลงใน `public/docs` ก่อน Next.js การเปลี่ยนหน้าเอกสารอัปเดตทิศทางและ SEO แคชเซิร์ฟเวอร์แยก origin และภาษา/เส้นทาง จำกัด 128 รายการ อายุห้านาที และลบผลเรนเดอร์ที่ล้มเหลว ETag ตรงกันจะตอบ `304` โดยไม่มีเนื้อหา

Pages ใช้ `build:pages` และ `check:pages` ด้วย `SITE_URL` แบบเต็ม เมทาดาทาของเว็บสถิติกำหนดตอน build ส่วนแคชและ ETag ของแอปเป็นพฤติกรรมในโหมดเซิร์ฟเวอร์ การส่งออกไม่แก้ซอร์สที่กำลังทำงาน ดูวิธีพัฒนาใน `DEVELOPMENT.md`

```text
src/components/
├── landing-page.tsx
├── layout/
├── controls/
├── sections/
├── previews/
├── motion/
├── graphics/
├── shared/
└── styles/

page.tsx → locale + dictionary → LandingPage → Next.js SSR
/docs/ → /docs/en/ → VitePress article
```
