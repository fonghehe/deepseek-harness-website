# 학습 경로

먼저 페이지를 열고 관련 소스를 읽습니다. 여섯 실습에서 카드, 언어, 캐시, 애니메이션, 문서 메타데이터, 리소스를 변경하거나 확인합니다.

## 읽기 순서

영어와 아랍어 페이지를 좁은 화면에서 열고 키보드 조작, 동작 줄이기 설정, JavaScript를 끈 상태를 확인합니다. 이어서 언어 등록 정보와 CSS, 언어별 페이지를 읽고 라우트, 렌더링, SEO, 캐시를 따라갑니다. 마지막으로 VitePress, Vue 테마, 문서 라우트에서 정적 생성과 서버·클라이언트 처리를 구분합니다.

## 실습 1: 공통 카드 수정

기존 카드의 문구를 모든 지원 언어에서 개선하되 ID와 링크는 유지합니다. 서버가 보낸 HTML과 하이드레이션 후 DOM을 비교하고, HTML 기본 펼침 요소, 아랍어 레이아웃, 기존 데모 네 개를 확인합니다. 서버와 클라이언트는 같은 템플릿을 사용해야 합니다.

## 실습 2: 다국어 처리 흐름 추적

일본어와 아랍어가 언어 등록 정보에서 경로, `lang`, `dir`, 표시 이름, 문서, 대체 언어 링크로 이어지는 흐름을 추적합니다. 언어를 바꿔도 쿼리 매개변수와 URL 프래그먼트, 현재 문서가 유지되는지 확인합니다. 새 언어를 추가할 때 필요한 변경도 정리합니다.

## 실습 3: 캐시 분리

```sh
curl -i http://localhost:3100/docs/en/architecture/
curl -i -H 'If-None-Match: W/"COPY_THE_RETURNED_HASH"' http://localhost:3100/docs/en/architecture/
```

응답에서 받은 실제 ETag로 다시 요청해 본문 없는 `304` 응답을 확인합니다. 다른 언어로 요청하거나 `SITE_URL`을 설정하지 않은 상태에서 미리보기 호스트를 바꾸면, 각각에 맞는 canonical URL과 ETag가 생성되어야 합니다.

## 실습 4: 동작 회귀 찾기

동작 줄이기 설정을 켰을 때도 첫 화면이 보이는지 확인합니다. 초기 opacity 값에 머물러 내용이 사라지는 오류가 왜 생기는지 설명하고, 화면 안의 가시성, 활성 탭 여부, 30fps 제한, DPR이 동작에 미치는 영향을 같은 조건에서 측정합니다.

## 실습 5: 이동 후 문서 SEO

설명 데이터와 frontmatter를 맞춘 뒤 문서와 언어를 바꿉니다. canonical URL, 링크 공유용 메타데이터, 읽기 방향이 현재 문서에 맞게 바뀌는지 확인하고, 이전 메타데이터를 제거하고 뒤늦은 갱신을 취소하는 방법을 설명합니다.

## 실습 6: 컴포넌트와 입력

`capability-demos.tsx`, `use-demo-scene.ts`, `assets.json`을 읽고 애니메이션의 한 단계를 변경합니다. 일시 정지와 가시성 제어는 유지하고, 리소스 파일이 실제로 바뀐 경우에만 해시를 갱신합니다. 생성된 청크가 `/harness-source/` 경로를 요청하지 않는지도 확인합니다.

## 성과 설명

방문자가 겪는 문제, 이를 해결하는 코드, 검증 결과와 남은 한계를 설명합니다. 직접 구현한 부분과 원본 사이트에서 가져온 디자인을 구분하고, 모바일 렌더링 비용과 필요한 수동 검수도 밝힙니다. `pnpm verify`와 관련 브라우저·성능 검사를 실행한 뒤 [아키텍처](../architecture/)의 흐름과 비교합니다.

## 개선 과정을 끝까지 추적하기

아래 파일에서 긴 작업을 찾고 작은 변경 후 전송량, 조작과 스냅샷을 비교합니다. 보고서는 버전 관리 밖에 둡니다. 기준 이미지를 갱신하기 전에 차이를 검토하세요. 로컬 이미지는 원본과의 픽셀 일치를 증명하지 않습니다.

```sh
pnpm analyze
pnpm perf:repeat
pnpm test:visual
```
