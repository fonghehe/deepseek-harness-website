# サイトの要件

ページの変更や公開前の確認に使うチェックリストです。変更したファイルと動作に合わせて確認項目を選んでください。

## 受入条件

| 領域       | 確認する結果                                                         |
| ---------- | -------------------------------------------------------------------- |
| 情報       | 全アニメーションを見ずに主題と次の行動が分かる                       |
| レイアウト | 長い言語名、メニューとコードが狭い画面に収まる                       |
| 対話       | ハイドレーション後のリンク、キーボードとスクリプトなしの詳細が使える |
| 言語       | すべての言語版の文言、文書、方向とメタデータが整合する               |
| SEO        | 移動後も canonical と共有 URL が現在の記事を指す                     |
| 配信       | origin／言語を混ぜず、条件 304 に本文がない                          |

翻訳、フォーカス順、混在方向の記号は人手でも見ます。

## コミットする入力

React、Hook、CSS、Markdown と静的リソースをバージョン管理します。JavaScript と CSS は `pnpm build` で生成し、`.next` と `public/docs` は Git の管理対象から除外します。`tests/fixtures/assets.json` に基づくチェックで静的リソースの整合性を確認し、取得した HTML や元サイトの実行コードが再導入されるのを防ぎます。

`.next/`、`public/docs/`、文書キャッシュ、テスト結果と `node_modules/` は再生成する出力です。秘密値や個人設定はローカルに保ちます。Git の ignore はアクセス権の代わりにはなりません。

## 変更の検証

```sh
pnpm verify
E2E_PORT=3101 pnpm test:e2e
```

本番構築後、空きポートで影響に対応したブラウザーテストを行います。文章変更は全版と共通 description を合わせます。リソースの hash 不一致は原因を調べ、安易に checksum を書き換えません。

## 公開前の確認

`pnpm build` で文書を先に生成し、完全な `public` を配信します。`SITE_URL`、既定の英語版へのリンク、多言語、404、sitemap、黒い favicon、デモ操作、動的 chunk を確認します。公開ドメイン上の SEO とリモート CI はローカル構築と別の証拠です。

## 性能と保守

容量と LCP、CLS、blocking time を合わせて評価します。キャッシュ速度はクライアント JS のコストを消しません。歴史的 baseline を失敗回避のために置き換えず、記事拡張の容量は明示的にレビューします。リソースやアニメーションを更新するときは、コンポーネントと CSS の変更を対応させ、出典、チェックサム、操作と再生の動作を確認します。

[学習ガイド](../learning/)で実践してください。

中国語だけ WeChat QR を表示し、他の言語は https://x.com/deepseek_ai へリンクします。

## 自動化以外の確認

言語とダウンロードのメニューでキーボード、Escape、フォーカス復帰を確認し、読み上げでコピー通知を検証します。実機でスクロールとアニメーション段階を確認します。アラビア語の長文と方向が混在するコマンドも確認します。端末、ブラウザー、動きの設定と証拠を記録し、訳文は母語話者が確認します。

```sh
pnpm verify:full
SITE_URL=https://example.github.io/repository/ pnpm build:pages
SITE_URL=https://example.github.io/repository/ pnpm check:pages
SITE_URL=https://example.github.io/repository/ pnpm perf:pages
```
