# 官網建設要點

修改頁面或準備發佈時，可以按下面的清單檢查。根據改動選擇驗證項，並記錄實際結果。

## 面向體驗的驗收矩陣

| 方面       | 驗收結果                                    | 專案證據                |
| ---------- | ------------------------------------------- | ----------------------- |
| 資訊組織   | 不播放全部動畫也能理解定位和下一步          | 首屏、分區和詳情折疊    |
| 品牌一致性 | 字型、圖示、表面一致，favicon 為黑色        | 本機品牌和 CSS          |
| 響應式     | 長標籤、選單和技術塊配合窄屏                | 阿拉伯語 390px 檢查     |
| 導航       | Hydration後連結有效，語言切換保留參數和片段 | 語言和路由測試          |
| 漸進增強   | 無 JavaScript 時核心文字、連結和詳情可用    | 無腳本瀏覽器場景        |
| 無障礙     | 焦點合理，減少動態效果不隱藏內容            | 鍵盤、動效和 axe 檢查   |
| 國際化     | 多語言內容、元資訊和文章對齊                | `check:i18n` 與文件測試 |
| 可發現性   | canonical、alternate、分享資訊屬於目前頁面  | 響應與用戶端導航檢查    |
| 交付       | 不串域名或語言，304 無響應體                | 快取測試                |
| 資源       | 輸入依賴齊全，配合可重複                    | manifest 和資源驗證     |

人工驗收還需追蹤閱讀順序、翻譯、換行、阿拉伯語混排和行動文案。截圖與單一分數不能證明全部結果。

## 應提交的原始碼與應忽略的產物

| 路徑                                                                | 是否提交 | 原因                             |
| ------------------------------------------------------------------- | -------- | -------------------------------- |
| `src/`、各語言 Markdown、`docs/.vitepress/`                         | 是       | 可維護原始碼和設定               |
| `src/components/`、`src/hooks/`                                     | 是       | 自有元件與動效生命週期原始碼     |
| `tests/fixtures/assets.json`                                        | 是       | 靜態輸入清單與 hash              |
| `public/brand/`、`public/fonts/`、`public/icons/`、`public/images/` | 是       | 品牌、字型、檔案圖示與中文 QR 碼 |
| `.next/`                                                            | 否       | 目前專案可重新建置的輸出         |
| `public/docs/`                                                      | 否       | VitePress 可重新生成的文件輸出   |
| VitePress 快取、報告、`node_modules/`                               | 否       | 快取、測量產物、已安裝依賴       |
| `.env.example`、共享編輯器/agent 文件                               | 是       | 可移植設定與說明                 |
| `.env.local`、個人覆蓋、憑證                                        | 否       | 私密或機器專屬狀態               |

`public/harness-source` 和捕獲 HTML 已刪除。網站 JS/CSS 由本儲存庫維護的元件和樣式經過 `pnpm build` 生成。只保留品牌、字型、檔案圖示與中文 QR 碼等靜態輸入，建置中的 hash 文件屬於可重新生成的輸出。

## 可移植的協作環境

使用儲存庫聲明的 Node、pnpm 和鎖文件。共享編輯器設置只描述專案任務，個人 MCP、憑證和歷史狀態留在本機。`AGENTS.md` 是統一指令入口，`AGENT.md` 是兼容說明，不代表所有工具自動識別單數文件。Git 和索引忽略規則不能替代文件權限。

## 修改內容後的驗證

1. 修改可維護內容或文件，同步其他語言和共享描述。
2. 官網檢查初始 HTML 與 Hydration 後 DOM；文件檢查文章間和語言間導航後的狀態。
3. 執行格式、翻譯和建置檢查；觸及路由、SEO、方向或控制項時增加相關瀏覽器回歸。
4. 檢查窄屏、減少動態效果和阿拉伯語 命令標點。

```sh
pnpm format:check
pnpm check:i18n
pnpm docs:build
pnpm verify
E2E_PORT=3101 pnpm test:e2e
```

使用空閒端口，瀏覽器測試前完成生產建置。文件改動不應順帶修改示範元件；hash 不符時先查差異，再決定是否有意更新驗證值。

## 發佈與部署清單

- `pnpm build` 先生成文件，部署保留完整 `public`。
- 設定實際生產 `SITE_URL`，在部署域名檢查 canonical 與分享 URL。
- 驗證文件預設英文、多語言入口、404、sitemap 和黑色圖示。
- 檢查示範、複製、下載與動態 chunk 請求。
- 確認 HTML、框架生成 chunk 和真正內容 hash 資源使用不同快取策略。
- 分開報告本機結果、遠端 CI 和線上驗收，不把建置透過等同於部署成功。

## 效能與長期維護

載荷和 HTML 大小要結合 LCP、CLS、阻塞時間觀察。熱快取計時衡量伺服器端交付，不代表瀏覽器執行成本消失。歷史基線不得為了透過檢查而覆蓋；擴寫文章時應明確評審內容體積預算，不放寬無關官網頁面限制。

透過元件、示範時鐘與 CSS 修改場景，保持暫停、離屏和減少動態效果的契約。靜態輸入變更後經評審更新 hash。中文頁腳保留微信QR 碼，其他語言頁腳統一跳轉 `https://x.com/deepseek_ai`。

繼續[學習路徑](../learning/)完成實踐。

## 自動檢查之外的驗收

用鍵盤檢查語言與下載選單、Escape 和焦點恢復，用讀屏器驗證複製回報。在真實手機檢查滾動與動畫階段。阿拉伯語還需檢查長文案和混合方向的命令。記錄瀏覽器、設備、動態效果設置和證據。譯文需由母語使用者確認，字段驗證不能替代語言審校。

```sh
pnpm verify:full
SITE_URL=https://example.github.io/repository/ pnpm build:pages
SITE_URL=https://example.github.io/repository/ pnpm check:pages
SITE_URL=https://example.github.io/repository/ pnpm perf:pages
```
