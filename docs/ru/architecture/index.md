# Архитектура

Сайт создаётся из React-компонентов, хуков и CSS этого репозитория. Next.js отвечает за серверный рендеринг (SSR) и гидратацию. Захваченный HTML и скомпилированное приложение оригинального сайта не загружаются. Изображения бренда, шрифты, иконки файлов и QR-код WeChat используются как статические ресурсы.

## Каталоги компонентов

Точка входа остаётся в `landing-page.tsx`. Компоненты сгруппированы по ответственности: макет, элементы управления, демонстрации и GPU. В `previews/` рядом находятся JSX иллюстраций, контейнерные запросы и временные шкалы; `graphics/` объединяет рендереры, геометрию и шейдеры. Текстовые помощники находятся в `shared/`, общий хук воспроизведения — в `src/hooks/use-demo-scene.ts`. Прямые импорты модулей без общего файла реэкспорта позволяют увидеть границы сервера и клиента и отложенную загрузку GPU.

```text
src/components/
├── landing-page.tsx    # Композиция страницы
├── layout/             # Шапка, подвал и бренд
├── controls/           # Язык, загрузка, копирование и контакты
├── sections/           # Разделы демонстраций и карточки
├── previews/           # Пять иллюстраций и временные шкалы CSS
├── motion/             # Появление, перспектива и движение CTA
├── graphics/           # Сцены Three.js, шейдеры и геометрия
├── shared/             # Заголовки и форматированный текст
└── styles/             # Переменные дизайна, адаптивность и RTL
```

## Композиция компонентов

```text
page.tsx → locale + dictionary → LandingPage → Next.js SSR
layout.tsx → html lang / dir
browser → generated chunks → client events / demo state
/docs/ → /docs/en/ → VitePress article
```

## SSR и языки

Страница проверяет язык и передаёт словарь props в общий LandingPage. Сервер и клиент используют один JSX. RichText понимает только разрешённые теги, не вставляя произвольный HTML. Корневые layouts групп маршрутов задают lang и dir на сервере.

## Управление воспроизведением

`use-demo-scene` объединяет видимость, передний план, уменьшенное движение и паузу. CSS `animation-play-state` сохраняет позицию без React-рендера каждого кадра; workflow меняет сценарий после каждого цикла.

## Жизненный цикл Canvas

`ParticleField` загружает сцены Three.js только в видимой области и на переднем плане. `RawShaderMaterial` сохраняет авторский GLSL и цвета жидкости; `InstancedBufferGeometry` рисует плитки одним инстансированным вызовом. `compileAsync` готовит программы параллельно там, где это поддерживается. Рендеринг ограничен 30fps и CSS-пикселями; вне экрана и в фоне он останавливается. Уменьшенное движение исключает GPU-аллокации; очистка освобождает geometry, material, texture и renderer.

Framer Motion отвечает за пружины навигации, появление секций и перспективу при прокрутке без React-рендера каждого кадра. Четыре демо сохраняют CSS-шкалы 22s, 17.5s, 11s и 15s, масштабирование и позицию паузы.

## Доставка документов

VitePress/Vue генерирует public/docs, Next.js доставляет с одного origin. Автономные dev/preview тоже открывают английский. Vue-тема обновляет направление/SEO, удаляет старые узлы и отменяет устаревшие обновления.

## SEO и кеш статей

`website-metadata.ts` использует Metadata API Next.js с `SITE_URL` или источником запроса предпросмотра. Для арабского языка не предполагается конкретный регион. Кеш статей VitePress разделяет источники и статьи, хранит не более 128 записей в течение пяти минут и удаляет записи с ошибками рендеринга. При совпадении слабого ETag возвращается ответ `304` без тела.

## Исходные ресурсы и сборка

Компоненты, хуки, CSS, Markdown и статические ресурсы хранятся в системе контроля версий. `pnpm build` генерирует JavaScript и CSS; `.next` и `public/docs` исключены из Git. Проверки по `tests/fixtures/assets.json` подтверждают целостность ресурсов и предотвращают возврат захваченного HTML или чужого кода приложения.

Только китайский показывает WeChat QR; остальные языки ведут на https://x.com/deepseek_ai.

Поддержка собственных исходников делает код понятнее, но сама по себе не подтверждает точность графики, все операции или мобильные показатели. Исторические отчёты относятся к прежней версии. Перевод, фокус и смешанное направление проверяют вручную.

Подробности раскрывает основная английская версия. [English](../../en/architecture/)

## Публикация сайта

GitHub Pages публикует сайт и всю документацию как статические файлы. `pnpm build:pages` использует фактический URL и префикс репозитория; `pnpm check:pages` проверяет локальные ссылки и SEO. Обычный сервер Next.js сохраняется. Origin отдельного запроса, заголовки кеша приложения и условные ETag документов относятся к серверной доставке; Pages определяет метаданные при сборке. Инструкция находится в `DEVELOPMENT.md`.

## Границы рендеринга и публикации

Статические иллюстрации файлов и трассировок выводятся сервером. Управление воспроизведением и смена сценариев workflow работают на клиенте. Большое дерево SVG плагинов сохраняет клиентскую границу, ограничивая сериализацию HTML/RSC. Перед переносом границы сравнивайте HTML и скрипты.

```text
locale registry → deployment paths → Next.js / VitePress → metadata
server content → client controls → CSS playback / Three.js lifecycle
verify:full → Pages export → static tests + budgets → publish artifact
```

- `src/config/deployment.ts`, `src/i18n/locales.ts`
- `src/components/sections/capability-demos.tsx`, `capability-demo.tsx`
- `src/components/previews/plugins-demo.tsx`, `workflow-preview.tsx`
- `tests/tools/build-pages.mjs`, `.github/workflows/quality.yml`
